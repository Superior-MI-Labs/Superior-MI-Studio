# Phase 4: control-condition and ordered-call input reconciliation (v2.105)

## Decision

Continue extending the already-qualified `ProgramGraph.replace_input`
reconciliation path. Do not introduce a second AST importer, execution editor,
source-region database, or view-session owner.

## Supported edits

- `python.branch.condition`: replace the existing Boolean producer selected by
  the test expression of a two-arm `if`.
- `python.require.condition`: replace the existing Boolean producer in the
  canonical `if not condition: raise ValueError(...)` guard; the raising effect
  and continuation must remain identical.
- `python.call_exec` data arguments: select an existing same-function producer
  with a matching typed input; preserve execution pin, callee, call order and
  output contract. Parameter positions derive from the existing callee function
  signature, never the execution-pin position.

Source changes only propose commands. The authoritative trial graph must
validate, lower, and reproduce the entire edited source. Linked generated
source still requires exact generated bytes. Independent functions may use
only the already-proven branch-local pure-order policy. No new node, control
edge, effect, or source text is created or overwritten by reconciliation.

## Evidence and failure policy

For independently authored functions, Branch/Require edits report spans of
original condition expressions, not entire blocks; the AST proof retains
control-suite order. If the condition cannot be mapped uniquely, the optional
span is omitted. Stale graph revisions and changed source SHA/revisions refuse
import. Review is read-only; commit requalifies and uses one undoable graph
transaction.

## Release qualification

Focused test files: `test_v2105_control_condition_reconciliation.py` and
`test_v2105_execution_call_argument_reconciliation.py`. Run the full
`bash scripts/agent-verify.sh --headless` gate, manifest/integrity checks and
an isolated installer; native Qt on Linux Mint is the release promotion gate.
