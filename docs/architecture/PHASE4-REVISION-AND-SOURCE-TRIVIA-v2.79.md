# Phase 4 v2.79 — Repeat import recovery and source-owned Python trivia

## Evidence / defect

Host report `qualification-20261101-214015-26093.tar.gz` for v2.78 failed at `QT_STAGE program-linked-source-document-reconciliation`, `qt_smoke.py` line 690. The GUI's `import_linked_python_source()` returned `False` because `LinkedPythonSource.import_edits()` rejected any changed `ProgramGraph.revision`. The smoke sequence imported once, performed Undo → Redo, saved the restored graph and the source, then attempted another source edit. Both graph *content* and the generated Python had returned to the linked state, but undo and redo intentionally advanced the monotonic revision counter. Previously no headless test replayed that exact sequence.

## Approved correction

- Preserve optimistic revision checks. When a different graph revision is observed, compare a SHA-256 of **all** canonical graph fields except the revision number, including program/function/node identities, port and edge contracts, annotations and layout. Only an exact restored snapshot can advance the link's expected revision; any different field refuses import. Never infer equality solely from generated Python bytes.
- Preserve the `ProgramGraph` transaction owner, `SourceDocumentSession` source owner and `python_lowering` compiler. No Qt-level import algorithm, second interpreter, additional document store or source writer.
- Preserve source-owned comments, whitespace and equivalent formatting when linking an existing `.py` file. Existing attach still requires a clean, byte-exact generated baseline. The subsequent source-owned import pairs canonical mapped assignments with the corresponding assignments in edited AST, then validates the *complete* AST against re-lowered generated Python after applying the proposed bounded literal/operator commands to a trial graph. Comments are not graph-owned; authored source bytes stay untouched until the source session explicitly saves.
- Source-only trivia yields no graph edit and advances the source receipt. Subsequent supported edits can still be reconciled; a saved source with comments remains independently owned and is not canonicalized by graph save.
- The generated-Python modal editor remains byte-exact and must not accidentally broaden its acceptance rules.

## Limits and no-go

This is **not arbitrary independent `.py` import**. Linking initially still requires exact generated bytes; arbitrary new statements, reordering, unqualified constructs, changed control semantics and incompatible ASTs are refused. All comments and formatting remain under the source owner, not persisted in `.smi-graph`. Relinking an independently saved commented `.py` from a new session still needs a future explicit source/graph region correspondence format. There is no silent automatic synchronization or source rewrite.
